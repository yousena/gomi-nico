# 要判断メモ：「隔週」「月ごとに日付が違う」収集への対応（2026-10-29）

太平さん向け。まとまった時間が取れたときに読んで、最後の「判断してほしいこと」だけ決めてください。**今すぐ決めなくても、自治体の追加は「毎週同じ曜日／第n曜日」で表せる町で進めています。**

## 何が問題か（ひとことで）

ごみニコのカレンダーは、収集日を次の2通りでしか登録できません。

1. **毎週同じ曜日**（例：燃えるごみは毎週月・木）
2. **毎月、第n曜日**（例：燃えないごみは第1・第3水曜）

ところが、追加したい町の一部は次のような決め方をしています。**このやり方だと、今の仕組みでは正しい日付を出せません。**

| 方式 | 例 | なぜ登録できないか |
|---|---|---|
| **隔週**（2週に1回、交互） | 川島町：水曜に「びん・かん」と「不燃ごみ」が1週おきに交互 | 「第1・第3」ではなく「2週間おき」。月をまたぐと1・3週の並びがずれて、実際の日と合わなくなる |
| **月ごとの特定日** | 葉山町・城里町・日高市の古紙：4/8、4/22、5/13、6/10… | 毎月の日付が不規則（4〜5週おき、祝日で振替など）で、規則性がない |
| **週ごとに曜日が違う** | 上三川町（栃木）の紙・布類：「第1木曜・第3水曜」 | 今の仕組みは「第1・第3の水曜」のように曜日を1つしか指定できない。第1週と第3週で曜日が違うと登録できない |
| **カレンダーの行で数える週** | 邑楽町（群馬）：「第2・4週の火曜」。実際のカレンダーでは4/5〜11の週と4/19〜25の週（行の2段目・4段目）に当たる | 今の「第n曜日」は「その月の2回目の火曜（4/14）」と数える。邑楽町の数え方だと4/7・4/21になり、日付がずれる。月によってずれ方が変わる |

間違った日を表示すると、住民がごみを出し間違えます。それは信頼を失うので、**無理に近似せず見送っています。**

## 解決するとどうなるか

見送り中の町が着手できます：日高市（埼玉）、松伏町（埼玉）、川島町（埼玉）、千代田町（群馬）、葉山町（神奈川）、城里町（茨城）、射水市（富山）、伊達市（福島）、上三川町（栃木）、邑楽町（群馬）など。数はまだ増えそうです（隔週は全国的に多い方式）。

（参考）下野市（栃木）・利根町（茨城）は、収集日が「色分けされた日付入りカレンダー」だけで公開されていて、曜日ルールの文章がありません。これは仕組みの問題ではなく、カレンダー画像を1か月ずつ目で読み取る作業の問題です。

## 選択肢

- **案A：「隔週」だけ対応する（おすすめ）**
  収集日のデータに「基準日（例：2026-04-15）から14日おき」と書ける形を追加します。川島町・松伏町・千代田町が主に対象。変更は小さめです。
- **案B：「特定日のリスト」にも対応する**
  日付をそのまま並べて登録できる形を追加します。葉山町・城里町・日高市・射水市が対象。自治体ごとに日付を打ち込む手間は増えますが、どんな方式にも対応できます。上三川町（週ごとに曜日が違う）・邑楽町（行で数える週）も、日付で登録すれば表せます。
  - 小さな追加で済む部分もあります：「第1木曜・第3水曜」は「曜日の指定を複数書ける」ようにするだけで対応でき、「行で数える週」は「カレンダーの第n行」という指定方法を足せば対応できます。
- **案C：対応しない**
  今まで通り、曜日・第n曜日で表せる町だけ追加します。安全ですが、追加できる町がどんどん減っていきます（すでに候補不足の状態です）。

## 判断の際の注意（リスク）

- A・Bとも、**全自治体共通のカレンダー計算（`public/script.js`と`src/lib/renderCityPage.ts`）を触ります。** 既存132自治体の表示が変わっていないか、変更前後で比べる確認が必要です。
- 画面の見た目は変わりません（DSの変更なし）。

## 判断してほしいこと

1. A・B・Cのどれにするか（私のおすすめは **A → 必要になればB**）。
2. 「A（またはB）で進める」場合は、その旨を一言いただければ、計算ロジックの変更・既存自治体の回帰確認・対象の町の追加まで、こちらで進めます。
